Speculate first. Cancel if wrong. Never freeze.

Most agents treat an interruption as cleanup bolted onto a request/response loop. This one flips that: speculating before the user finishes talking is the default, and cancellation is the same mechanism running on almost every turn — not a special case.

The one data structure everything hangs off

SlotState is a session-scoped slot store with a monotonically increasing generation counter. Bump the generation — on an interruption, or a slot correction that disagrees across modalities — and every in-flight call tagged with a stale generation gets cancelled via its own trio.CancelScope. No polling, no manual bookkeeping per call site. The Flights and Support pages on this site are both just different tool manifests pointed at the same engine below.

Why a real backend, not a mock

server/app.py runs a real Agent per browser tab — fresh SlotState, fresh cancellation scopes, same code path as the test suite and demo.py. The Flights page connects with domain: "flights", the Support page with domain: "support"; the server filters the tool manifest per domain before the agent ever sees it, so each page's agent genuinely only knows about its own tools.
